WHAT THIS IS
------------

Pass 1 was the rules. This is the module: commands, a read side, a schema, an HTTP surface, and
the contract Sales will use in pass 3.

The interesting file is Persistence\Repositories\PricingRepositories.cs — specifically
PriceCandidateSource, which is one join that fetches every live list pricing a part today. That
runs once per line on every counter sale, and it is written as one round trip rather than a
lookup per list for the same reason everything else here is: the difference between a screen that
feels instant and one that does not.

It deliberately does not filter by customer. Doing that in SQL would mean fetching the agreement
first and turning one query into two, and the resolver has to apply that rule anyway — it is a
domain rule, not an index. So the query stays index-shaped and hands back slightly more than is
needed.

IPriceProvider is the fourth module query contract, after IInventoryAvailability,
IPartnerDirectory and ICatalogDirectory. It returns null when nothing prices a part, rather than
an error — Sales knows the SKU and the order number and can say something useful; a contract
cannot. Pricing's own /quote endpoint answers with the reason, and that is what a person calls.


ONE FIX TO PASS 1
-----------------

PriceListEntry.Breaks used to return the backing list as-is and MinimumSaleQuantity read
_breaks[0]. Both were right in memory, because the aggregate sorts when a break is added, and
both would have been wrong the moment a row came back from PostgreSQL — an owned collection
materializes in whatever order the rows arrive, and there is no mapping-level ORDER BY to lean
on.

Breaks now sorts on the way out and MinimumSaleQuantity takes the minimum. BreakFor was already
order-independent, which is why the 88-check harness and the 51 tests all still passed with the
bug in place. That is the shape of this class of bug: nothing fails until there is a database.

KNOWN LIMITS
------------

1. No margin floor. "Never below cost plus 8%" needs the cost, which is Inventory's, and that is a
   fifth contract rather than a guess.

2. Cross-currency is refused, not converted, on both the quote endpoint and the contract.

3. Prices are per part. Category-wide rules ("15% off all Bosch filters") would be a second kind
   of entry and a second resolution step, and the resolver is deliberately simple enough to
   reason about today.

4. Nothing consumes PriceChangedIntegrationEvent yet. It is published so the outbox has the fact;
   the first consumer will be whatever screen holds a quote.
